# Basic Bash sanity track

Eight synthetic cases exercise four elementary operations on development and heldout data: descending size listing with valid `ls` flags, quoting a directory with spaces and a filename beginning with a dash, numeric sorting, and exact-line counting. Grading checks actual successful executions, output file bytes or listing fields, and preservation of the input files. Repairs are allowed within the outer Pi request budget. This is a secondary signal for a future CLI, not a coding benchmark or a substitute for research correctness.

`index.ts` exposes a single Pi `bash` tool, fixtures, session lifecycle and deterministic checks. `driver.py` requires Linux bubblewrap, Python 3, `ldd`, and the explicitly enumerated common shell utilities. It copies the resolved executables, dynamic libraries and Python standard library into a private root filesystem; it never binds a home directory, repository, full software store, host root or package environment. Missing tools, unsupported namespaces or failed canaries refuse execution. The toolchain content digest and successful containment checks are available from `session.ready` for the run receipt.

Every command runs in a fresh network/user/PID namespace with a read-only toolchain and an 8 MiB `/work` tmpfs. Only bounded regular-file snapshots persist between calls. A trusted supervisor captures at most 32 KiB per output stream and enforces a five-second command deadline, CPU/file/address-space/descriptor/process rlimits, and bounded snapshots (128 files, 128 KiB each, 512 KiB total). The namespace dies after the receipt is collected, killing background descendants. No `/proc`, host environment or network interface is exposed. The Python supervisor disables dumpability to protect its descriptors against child inspection. The track is designed for elementary shell operations; it does not promise a general hostile-native-code security boundary.

Run the free execution/containment regression with `./node_modules/.bin/tsx evaluation/shell/test-shell.ts` from the repository root. It requires the isolation dependencies and fails rather than skipping or running on the host. Candidate inference and spending remain the responsibility of the stock runner.
