# Personal memory publication

Personal memory is opt-in and separate from the shared corpus. A completed conversation turn is bound to a stable turn ID, conversation ID, archive revision, immutable raw-record range, consent generation and per-stage coverage, then committed to IndexedDB before background processing starts. New jobs reference the separately persisted raw archive instead of duplicating transcript payloads; legacy inline jobs remain readable. Model configuration and credentials are never part of a saved job.

Audit, memory and summary run in that order on private drafts. Only successfully acknowledged audit evidence crosses declared handoffs: memory reads spelling and stale-description findings, while summary reads supported spelling alone. Each stage publishes its owned fields, action buffer and completion acknowledgement in one revision-checked transaction through `MemoryStorage`. The runtime exposes only committed state; failed or cancelled stages discard their drafts. Network calls and tool execution occur outside storage transactions.

One serialized runtime updater handles stage publications, review-flag resolution and retrieval counters. Retrieval may change only existing nodes' hit counts and last-fired timestamps; semantic and structural writes are rejected. A stage publication incorporates counter changes made while its draft was running. Other stages' summaries, flags and action buffers are taken from the current committed state at publication, rather than from the draft's earlier snapshot.

Reload reopens unacknowledged stages against committed state. Acknowledged stages are not replayed, including a stage committed immediately before the page closed. If a stage fails, later turns remain durably queued to preserve chronological ownership; the memory indicator offers retry, while foreground chat and corpus tools remain available. Confirmed source-conversation deletion instead cancels its unfinished work with durable receipts, invalidates in-flight drafts and permits other conversations to proceed; unreadable or changed history remains a failure. Audit must complete before the corresponding memory stage begins. Retry resumes the oldest unfinished turn, retaining successful sibling-stage acknowledgements.

Consent revocation and memory replacement immediately invalidate in-flight authority, abort model requests and persist a new generation without pending jobs. Replacement waits for earlier publications to settle. Cross-tab revision conflicts disable that page's writer until reload, retaining the other tab's data. A completed job retains a compact active receipt without its transcript or speech evidence; per-conversation archive coverage survives active receipt rotation. Durable role records retain requests, messages, tool results, typed outcomes, action notes and summaries outside active prompt windows; eviction of legacy active records archives their content before removing them.

The local inference gateway controls queue and execution timeouts separately. Each background role also has a qualified cumulative output-token allowance across its windows; missing or malformed usage fails closed, and exhaustion leaves explicit outstanding coverage rather than acknowledging a partial draft. Waiting for a slot does not consume a whole-stage wall timeout. Truncated or unsuccessful completions never publish a draft.

Offline regression coverage is in `scripts/test-memory-stages.ts`, `scripts/test-memory-lifecycle.ts` and `scripts/test-memory-storage.ts`. The stage fixtures reconstruct reloads from every admission, stage-intent and stage-commit boundary, and exercise failed publication, consent races, cross-tab conflicts, concurrent counters and explicit retry ordering.

## Bounded role context

The implementation uses persisted content-prefix digests and message counts to identify appended, uncovered input. Digests exclude usage counters so background accounting does not replay old conversation. A changed prefix, such as imported or compacted history, falls back to the available captured records with their source labels; it never assumes that only the last user message matters. The transcript remains saved with unfinished work but is not dumped into each model request.

Each role packs adjacent messages into windows using the installed provider serializer and the role's actual tokenizer budget, including policy and tool schemas. Large messages split into explicit character-offset spans carrying source identity, provenance and continuation markers. Every owned window runs on the same private draft; no intermediate window publishes or acknowledges mutations. Fixed policy/schema overflow is an explicit release-profile qualification failure. Serialized counts are cached within a window to avoid repeated tokenizer requests for identical payloads.

`memory_inspect` offers stage-scoped search, record handles and bounded reads for captured transcript, draft terms, committed and draft actions, prior summaries, raw speech evidence, the current summary draft, current evidence and archived tool results. A paged read retains the same record bytes across continuations; starting again at zero observes the current draft. Tool histories exceeding the request budget lose only complete older exchanges; their full text remains inspectable. The final assistant tool-call message and all matching results stay paired, with large results replaced by explicit read handles when needed.

Summary has read-only evidence tools and a private summary-draft write tool. Read/check/store/abstain let the model repair invalid drafts while it is running; terminal prose never becomes the stored entry. It revises its current conversation draft across windows and can inspect the prior committed entry rather than receiving all prior summaries. Prompts preserve the distinction between user statements, assistant proposals, generated summaries and untrusted reference material; reference instructions do not authorize personal-memory writes. These windowing and inspection choices are implementation decisions, not claims that a model has already passed memory-quality or latency qualification.

Window and inspection fixtures are in `scripts/test-memory-windows.ts`; production token measurement uses the installed tokenizer, while offline fixtures inject a deterministic cost function to exercise packing and overflow boundaries without network access.

## Durable role evidence

Background requests, completed messages, tool exchanges and outcomes remain in immutable primary-indexed personal-memory records outside capped active buffers, with bounded reads, model/profile identity, credential-free transport metadata and revision/consent checks; successful outcome/action/summary records publish atomically with stage acknowledgement. Export includes the archive in a consistent persisted snapshot, import and deletion replace it atomically, and revocation preserves saved records while invalidating pending writes; the archive uses the existing pipeline store without a database-version migration.

## Outcomes and retained evidence

Every evidence window requires an explicit outcome. Completed work and deliberate no-op acknowledge coverage; refused work pauses its dependants and is not automatically retried on reload. Failed, cancelled and budget-exhausted work remain distinct in retained receipts. A user-initiated retry can retry a refusal.

`memory_archive` reads only the requesting role's historical records and exposes full-text handles through `memory_inspect`; cross-role access uses the scoped current-job audit handoff. Failed and transient traces are diagnostic records, not completed findings. Role events are persisted during execution, and final action/summary/outcome records share the transaction that acknowledges the stage. Export/import and explicit deletion include these personal archives; no cloud collection is involved.

## Personal glossary review

The memory stage advances bounded persistent scans of new, changed and rotating terms, retaining unresolved candidate pairs and permanent ID-bound distinct/merge judgments; fingerprints identify reviewed content without expiring decisions, and premerge term snapshots remain inspectable in retained role evidence and exports. Settings exposes explicit user reconsideration for terms kept separate, which preserves the previous judgment and reopens review for a subsequent consenting turn; background roles cannot forget judgments, and failed or interrupted stages publish neither decisions nor scan advancement.
