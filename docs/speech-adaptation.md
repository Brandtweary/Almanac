# Browser speech adaptation

With personal memory enabled, the audit role can call `phonetic_candidates` for the current raw utterance. The browser scores the personal glossary and accepted correction observations using eSpeak IPA and normalized spelling. It sends bounded vocabulary and raw-speech spans to the configured backend for stateless pronunciation; glossary records, message identities, histories and descriptions stay in the browser. This is the same configured local/hosted backend boundary used by inference and embeddings, and requires personal-memory consent. Candidate reports retain raw UTF-16 span offsets, spelling provenance, distinct observation identities, scorer identity and explicit token/target continuation. Ordinary words require corroborated pair evidence; rejected pairs and accepted canonical spellings are protected. These are contextual review hints and never rewrite speech by themselves.

`add_auto_replace_rule` accepts optional `exact_case`. Exact-case rules require matching raw capitalization; old rules remain case-insensitive. Numerical changes and conflicting supported interpretations are refused. A raw-span-backed log, correction, rejection and replacement rule are separate operations. Imported rule casing must be a boolean. Typed text never passes through adaptation, and revoked memory consent invalidates asynchronous candidate results.

The scorer uses English-US eSpeak pronunciation with Unicode-preserving punctuation sanitation and a syllable-delta filter. It does not claim calibrated multilingual pronunciation quality. Candidate computation is paged for bounded work; `scope`, `next`, exclusions and `resultTruncated` describe the search actually performed. An empty page cannot establish that an entire utterance is correct.

## Pronunciation service

`POST /v1/phonemize` accepts `{texts: string[], language: "en-us"}` with at most 256 strings of 64 UTF-16 units, preserving Unicode letters, combining marks and numbers. It returns aligned `phonemes` and `engine: {name: "espeak-ng", version, voice: "en-us"}`. Requests are cancellable, carry no durable browser identifiers, and the service neither stores text nor logs request bodies. Candidate generation refuses malformed alignment and an engine identity change within a page. Missing pronunciation support reports unavailable; there is no cloud fallback and ordinary STT still works.

The browser does not bundle or link an eSpeak binary. The configured content service executes separately installed [eSpeak NG](https://github.com/espeak-ng/espeak-ng) through its command-line interface. Redistribution of the engine must carry its own [GPL license](https://github.com/espeak-ng/espeak-ng/blob/master/COPYING), applicable notices and matching corresponding source/build materials; the application's MIT license does not relicense the engine. Offline qualification includes the native executable and voice data independently from browser assets.
