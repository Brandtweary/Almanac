# Background operation coverage

This inventory separates deterministic tool contracts from observed model choices. The supplemental ten-candidate campaign is pending; its results must be linked here before interpreting the new cases as passes. The existing local observations are summarized in [local runtime results](local-runtime.md). The [supplemental cases and adapter](../evaluation/background-sanity.md) preserve the original benchmark inventory.


Mechanical coverage means the named source test checks a contract with deterministic inputs; it does not mean a model chose the right action. Model observations below refer to reviewed local receipts unless marked hosted. Existing local heldout and compatibility evidence used 24,576 context, with largest observed input 9,598 tokens.

The five-new-term ceiling and generic destructive recurrence are prompt rules. Mechanical transaction safety prevents partial/stale writes but cannot certify semantic correctness of a valid completed mutation. No fine-tuning is proposed. Existing benchmark scores remain untouched; supplemental development results receive their own report with exact runtime and source identities.

An evaluation receipt defect was corrected before the supplemental campaign: the initial glossary snapshot retained references to existing term objects, so changing a seeded term could also change the receipt's apparent before-state. This affected the snapshot, not tool execution. An inventory of 126 existing pilot, smoke and local receipts found that all began with empty glossaries; subsequently added terms do not enter the separate initial snapshot object. The previously reviewed local 15 heldout and two compatibility results are therefore unaffected. Historical receipt bytes and scores remain unchanged. The new regression checks that a seeded rename preserves the original before-state and term identity.

Review of the first background campaign identified fixture confounds: the voice/stale-description and glossary-repair scenarios expected retrieval-scoped audit work without supplying admitted retrieval context. The stale-description handoff also omitted a documented conditional reason requirement, and its evaluation handler returned an opaque missing-property error. Original observations and frozen judgments remain intact, but affected retrieval-scope and handoff-contract results need those qualifications. A [versioned two-case amendment](../evaluation/background-amendment-v2.md) supplies production recall delivery records and the clarified shared contract; corrected model results are pending review and execution. No production audit policy is loosened.

The typed historical-rule case also conflicted with the audit prompt’s blanket typed-input STT ban. The Arms matching expectation was unsupported: default `no_stem=true` retains plural normalization, so toggling it cannot remove the arm route. All three original background totals therefore remain diagnostic rather than clean comparative evidence. The [version 3 proposal](../evaluation/background-amendment-v3.md) clarifies existing historical-cleanup authority, corrects matching-interface wording, and records actual matcher outcomes; its model runs remain pending.
